研究目标：Sony A7C II（ILCE-7CM2）在全画幅、机械快门模式、机身识别到闪光灯或引闪器、关闭 HSS 的情况下，将普通闪光同步的最快可选快门从 **1/160 秒改为 1/200 秒**。修改的是机身快门同步参数，不是闪光灯的发光持续时间。

定位基线为 **A7C2 2.01**，对照样本为 **A7M4 6.02**。本仓库仅发布定位依据、最小修改方法及测试结果；不提供设备连接、写入或恢复工具，不分发固件、修改版参数文件、完整参数记录、机身备份、序列号或私人标定数据。

**当前结果：已在一台 A7C2 上完成参数写入、保存和回读校验；2026-11-21，机主反馈已完成重启与闪光实拍，未发现异常。** 结果来源及验证边界见下文。

## 一、定位依据

### 1. 用 A7M4 已知的 1/250 分支作对照

索尼官方规格：A7M4 的普通闪光同步速度为全画幅 **1/250 秒**、APS-C **1/320 秒**；A7C2 对应为 **1/160 秒**和 **1/200 秒**。[A7M4 规格](https://www.sony.com/electronics/support/e-mount-body-ilce-7-series/ilce-7m4/specifications) · [A7C2 规格](https://www.sony.com/electronics/support/e-mount-body-ilce-7-series/ilce-7cm2/specifications)

在两台机型中均定位到 BK4 记录 **`0x02A6001A`**，长度 **`0x80`（128 字节）**。下表为小端 16 位字段：

| 记录内偏移 | A7C2 2.01 原厂值 | A7M4 6.02 原厂值 | 已定位用途 |
| --- | --- | --- | --- |
| `+0x00` | `60 17` → 1/160 | `E0 17` → 1/250 | 基础同步边界，也参与闪光驱动模式阈值判断 |
| `+0x1C` | `60 17` → 1/160 | `A8 17` → 1/200 | 条件分支对基础同步边界的覆盖值 |
| `+0x20` | `A8 17` → 1/200 | `F8 17` → 1/250 | 画幅专用覆盖值 |
| `+0x54` | `A8 17` → 1/200 | `30 18` → 1/320 | 另一分支的画幅专用值 |

以上数值通过执行 A7C2 原厂换算函数核对。`0x17E0` 与 `0x17F8` 在该换算函数中都对应显示值 1/250；不要按编码差值自行推算快门分母。已核对 A7C2 的 12 份和 A7M4 的 16 份地区参数，表内字段在各自样本中一致。

A7M4 记录中存在条件用的 1/200，不代表它的普通全画幅上限是 1/200。内部条件与所有附件、菜单设置的完整对应关系尚未确定；不能把两个字段解释成“一个对应引闪器、另一个对应直插闪光灯”。

### 2. 参数与原厂读取代码对应

以下代码地址均为各自 **`cpapp-b.bin` 的文件偏移**，不是运行地址。对应 CP 运行地址需加 `0x108000`。

| 路径 | A7C2 2.01 | A7M4 6.02 |
| --- | --- | --- |
| 记录 ID → RAM 地址 / 长度映射 | `0xC883EC` → `0x01AA5E8A` / `0x80` | `0xB15E28` → `0x0148B80E` / `0x80` |
| 基础值 `+0x00` 读取 | `0x7888A4–0x7888B2`，指针保留基址时取 `[基址]` | `0x67AA86` |
| 条件覆盖值 `+0x1C` 读取 | `0x7888D6` | `0x67AAA4` |
| 闪光限制启用判断 | `0x7887AE` | `0x67A936` |
| 超限快门候选压回边界 | `0x2133E6–0x2133EC` | `0x1C1218–0x1C121E` |
| `+0x00` 的驱动阈值读取 / 比较 | `0x20F4BE` / `0x20F684–0x20F688` | `0x1D86B0` / `0x1D86D4–0x1D86D8` |

A7C2 原厂 CP 文件 SHA-256：

```text
f5a477588698ef965748903b8959a39ce4f59ffd4aee4d4234ef1670f56a1428
```

静态分析和原始函数执行表明：只改 `+0x1C` 时，一个全画幅基础分支仍返回 1/160；同时改 `+0x00` 和 `+0x1C`，本次构造的两种全画幅分支均返回 1/200。`+0x00` 还参与驱动模式判断，因此不能把影响范围描述为“只改变屏幕数字”。

## 二、最小修改

### 1. 修改对象

**以该台机身自己的参数备份为基础，按记录 ID 定位 `0x02A6001A`。** 核对记录长度 `0x80`、属性 `0x08`，以及下表原始值。记录不一致时，应重新分析，不能套用本方法。

| 记录内偏移 | 原始字节 | 修改后字节 | 修改后的值 |
| --- | --- | --- | --- |
| `+0x00` | `60 17` | **`A8 17`** | 1/200 秒 |
| `+0x1C` | `60 17` | **`A8 17`** | 1/200 秒 |
| `+0x20` | `A8 17` | 保留 | 原有 1/200 秒 |
| `+0x54` | `A8 17` | 保留 | 原有 1/200 秒 |

两处 16 位字段实际各只改变一个字节：`60 → A8`。记录其余 **124 字节**保持原值，记录长度、属性和表结构保持不变。

本次参数实验不修改 `appFw.so`、`cpapp-b.bin`、Bootloader、内核、启动脚本或 WBI。参数仍可能在启动加载、运行或保存期间被使用；没有改启动代码不等于保证开关机安全。

### 2. 原厂文件中的位置仅用于对照

本次 A7C2 2.01 中国版原厂样本在解包后的相对路径为：

```text
firmware.tar_unpacked/0110_backup/SYSIPSX-DSLR/PP/CX89701_CN1.bin
```

| 内容 | 该样本文件偏移 |
| --- | --- |
| 目标记录起始，也是 `+0x00` | `0x1CB2D0` |
| 目标记录 `+0x1C` | `0x1CB2EC` |
| 所属 BK4 段起始 | `0xED000` |
| 所属 BK4 内部校验字段 | `0xED020`，4 字节 |

该中国版原厂参数文件 SHA-256：

```text
b098e7b6147dc990e682411b02977c27260ddc2cde20ee11a949565808911d80
```

不要全文件替换 `60 17`，不要将这些文件偏移直接当作机身闪存地址，也不要用原厂整份参数或别人的备份覆盖机身。

直接编辑 BK4 副本时，必须重算目标段校验：从该段起始累计到 `dataOffset + dataSize`，排除该段 `+0x20..+0x23` 的校验字段自身，逐字节求和，以小端 32 位保存。每份备份须独立重算，不能复制另一文件的校验值。更新包还涉及外层校验、封装及参数保留策略；BK4 校验通过不代表可作为官方升级包刷入。

### 3. 本次实机采用的单记录接口

已在本机验证的流程为：读取并备份 → 核对 CP 直接读取值与内存、已保存参数一致 → 写入目标记录 → CP 回读 → 内存参数校验 → 保存所属子系统 → 两次已保存参数校验 → 最终 CP、内存回读。

| 操作 | 本次使用的接口参数 |
| --- | --- |
| CP 记录读取 | AdjustControl 分组 `0x603`，命令 `0x40`；负载为小端 `<II>(0x02A6001A, 1)` |
| CP 记录写入 | 同分组，命令 `0x41`；上述负载后追加修改后的本机 128 字节记录 |
| 保存所属子系统 | `saveBackup(0x02A6)` |
| 内存 / 已保存备份读取 | `getBackupPresetData(True)` / `getBackupPresetData(False)` |

这是已验证的一次实验调用顺序，不是通用 USB 操作教程或即用工具。身份绑定、接口认证、排他锁、回应长度与状态校验、原值核对和失败停止处理均需由实现方完成。写入结果未知时，不能盲目重试或继续保存。通过参数接口写入时由相机维护存储，不能把“离线改文件重算校验”当作直接写原始闪存的替代方案。

## 三、测试结果

截至 **2026-11-21**，区分离线测试、设备回读和机主反馈如下。

| 项目 | 结果 | 结果来源与边界 |
| --- | --- | --- |
| 原厂地区参数对照 | 通过 | A7C2 12 份、A7M4 16 份，核对同一记录的对应字段 |
| 原厂函数离线执行 | 通过 | 人工 RAM 中验证单字段与双字段差异；构造闪光限制状态时，双字段候选保留 1/160、允许 1/200，并将 1/250 压回 1/200 |
| 未启用闪光限制的构造状态 | 通过 | 同一候选限制代码未将 1/250 压回；不能代替全部空热靴实机回归 |
| 离线 BK4 修改与独立解析 | 通过 | 12 地区 × 2 方案；指定字段以外的属性、数据与记录结构保持一致 |
| 修改流程的离线故障测试 | 通过 | 6 项：写入/逆向逻辑、回读失败不保存、其他参数变化不保存、未知写入不重试、目标与负载范围限制、准备阶段禁止写入；逆向逻辑仅离线测试，不是实机恢复成功证明 |
| 本机目标记录原值 | 通过 | 内存、已保存参数重复读取，以及 CP 直接读取均一致 |
| 本机程序核对 | 相关窗口一致 | 实机 CP 已存在其他修改，整体不等于原厂；本次已定位的闪光同步函数与记录映射窗口与 2.01 原厂一致 |
| 单记录写入与保存 | 通过 | 一次目标记录写入、一次 `saveBackup(0x02A6)`，未修改程序或启动文件 |
| 保存后两次参数回读 | 通过 | 目标两处均为 `A8 17`；其余 **53,244 项属性**保持不变 |
| 最终内存与 CP 回读 | 通过 | 目标为 1/200；53,242 项其他属性不变，另两项为已识别的运行计数变化；随后正常退出服务模式 |
| 重启与闪光实拍 | **机主反馈通过** | 2026-11-21，机主确认已测试、未发现问题；本仓库未归档附件型号、通信模式、EXIF 和样张，不能将反馈扩展为所有附件和模式已验收 |

这次实机写入前后，目标记录 `+0x00`、`+0x1C` 均由 `60 17` 变为 `A8 17`，`+0x20`、`+0x54` 保留原值。机主随后报告重启与闪光实拍正常。

**该结果证明一次机身配置下的修改与反馈，不是对所有 A7C2、所有闪光灯/引闪器、HSS、空热靴、官方升级和长期使用的兼容性保证。** 特别是该机身的 CP 此前已有其他修改，本次结果不能写成“完全原厂机身全功能验证”。
